# BOSS 岗位核验助手（只读版）

在 BOSS 直聘的岗位详情页旁边挂一个侧边栏，告诉你**这个岗位值不值得投、为什么、证据在哪**。

它不会替你打招呼，不会替你发消息，不会替你点任何按钮。发送这件事全程是你自己做。

对应设计文档 `docs/superpowers/specs/2026-08-14-edge-boss-job-assistant-design.md` 的第 1、2 阶段。

## 为什么只做只读

自动发送在 BOSS 上是封号处理的。账号是社招唯一的投递渠道，赌不起。
所以这一版把「判断」和「动手」彻底切开：判断交给机器，动手留给你。

这不是「暂时没实现」，是**结构上保证做不到**：

- `manifest.json` 只申请 `storage` 一个权限，没有 `tabs`/`alarms`/`scripting`
- content script 里没有任何 `.click()` / `.submit()` / `dispatchEvent()` / 给输入框赋值的代码
- 后台没有 `chrome.alarms`，不存在「你不看着的时候它自己动」

这三条都有测试盯着（`tests/no-send-guard.test.js`），谁哪天顺手加一行就会红。

## 装

1. Edge 打开 `edge://extensions`
2. 右下角打开「开发人员模式」
3. 点「加载解压缩的扩展」，选中 `edge-boss-job-assistant` 这个文件夹
4. 固定到工具栏

## 配

点扩展图标 → 「配置」。默认画像已经按你的情况填好了（深圳、8–12K、AI 应用/Agent 方向、20–99 人小公司、只认技术负责人直招）。

要填的只有两个 Key：

| 配置 | 去哪拿 | 不填会怎样 |
| --- | --- | --- |
| 模型 API Key | DeepSeek 开放平台 | 只跑规则分，结论封顶到「待定」，不会给绿灯 |
| 检索 API Key | Tavily 或 Serper | 没有背调，缺可核验来源，同样不给绿灯 |

Key 只存在本机浏览器里，导出数据时会自动剔除。

**「简历事实库」这一栏是整个东西的地基。** 模型只能引用这里的条目当作「我会什么」的证据，
事实库里没有的技术和数字，它一律当你不具备。默认内容已经按仓库根目录的
《求职事实核验表》清过一遍——没跑过的指标（QPS、召回率、自动解决率、工单条数）
一条都没往里放。别为了让分数好看往里加，面试官会当场问。

## 用

打开任意一个 BOSS 岗位详情页，右上角自动出现侧边栏：

- **绿灯 建议投** — 分数够、背调没矛盾、至少有一条你能点开核对的来源
- **黄灯 待定** — 分数中等，或者证据不足，或者有中风险矛盾，值得你自己看一眼
- **红灯 别投** — 硬筛没过、分数太低，或者发现高风险矛盾

每条结论都能展开看依据：规则分每一项扣在哪、模型认为哪条 JD 要求对上了你哪个项目、
背调结论挂着哪个 URL 和哪段原文。**证据链接都是可点的，请真的点开核对**——
模型归纳会出错，URL 不会。

底部三个按钮：「我投了」「我跳过」只是给你自己记账用的，不触发任何页面动作；
「选择器自检」见下。

## 第一次用先做这件事

BOSS 的页面 class 名会改，改了抽取就会塌。

**打开第一个岗位页，先点「选择器自检」。** 它会列出每个字段是用哪层策略拿到的：

```
jobTitle: css:.job-banner .name h1  ← AI应用开发工程师
companyName: meta                    ← 深圳某某智能科技
salaryText: text-pattern             ← 10-15K·13薪
publisherTitle: MISS
```

- `css:...` 走的选择器，正常
- `text-pattern` / `meta` 走的兜底，能用但不精确
- 红色 `MISS` 没拿到，这个字段没参与判断

如果关键字段（职位名、公司名、JD）是 MISS，改 `src/content/boss-adapter.js` 顶部的
`SELECTORS` 表就行，全部选择器都集中在那一张表里。

## 花多少钱

一个岗位最多 2 次模型调用（匹配 + 背调归纳）和 3 次检索。

- 硬筛没过的岗位**一次调用都不花**——先本地筛掉再说
- 同一岗位 7 天内翻回去看走缓存，不重复计费
- 配置页有每日调用上限，默认 60 次；到顶了自动降级成纯规则分，不会偷偷继续烧

## 防幻觉

背调这一层最容易出幻觉，模型很乐意替一家它没听说过的公司编一段「主营 AI 解决方案」。挡了三道：

1. 提示词只喂检索到的片段，明确禁止使用模型自己的先验知识
2. 每条结论必须挂 URL + 原文摘录，**没有来源的结论会被自动改写成「信息不足」**
3. 校验层把不在检索结果里的 URL 全部丢掉——模型编的链接进不来

反过来也防：没有来源撑着的「高风险」指控会被降级为中风险，
免得一次幻觉把一个本来不错的岗位毙掉。

## 开发

```bash
node --test 'tests/*.test.js'
```

零运行时依赖，零构建步骤，改完代码在 `edge://extensions` 点一下刷新即可。

63 个测试覆盖：薪资/经验/学历解析、硬筛规则、打分权重、决策合并与降级、
模型输出校验与 URL 白名单、以及那条「不许发送」的结构性保证。

页面 DOM 抽取只测了文本兜底那一层——CSS 选择器只能对着真站点验，这就是自检按钮存在的原因。

## 没做什么

设计文档第 3–5 阶段全部没做，都是有意的：

| 没做 | 为什么 |
| --- | --- |
| 招呼语生成 | 生成完就想发，发了就是封号风险。要用话术自己写，或者单独找我 |
| 投递队列 / 自动发送 | 同上，这一版的整个前提就是不发 |
| 会话解析 / 自动跟进 / 自动回复 | 依赖持续读取聊天页，权限和风险都上一个台阶 |

要加这些之前，先想清楚一件事：**这个工具的作用是让你少投垃圾岗位，不是让你多投。**
每天有效投递数才是唯一指标，工具本身不产出 offer。
