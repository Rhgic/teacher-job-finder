# BOSS 岗位核验助手

在 BOSS 直聘的岗位详情页旁边挂一个侧边栏：**这个岗位值不值得投、为什么、证据在哪、招呼语给你写好了。**

默认把招呼语填进输入框就停手，发送键你自己按。要它自己点发送，得去配置页主动打开。

对应设计文档 `docs/superpowers/specs/2026-08-14-edge-boss-job-assistant-design.md`。

## 装

1. Edge 打开 `edge://extensions`
2. 右下角打开「开发人员模式」
3. 点「加载解压缩的扩展」，选中 `edge-boss-job-assistant` 这个文件夹
4. 固定到工具栏

## 配

点扩展图标 → 「配置」。默认画像已经按你的情况填好了（深圳、8–12K、AI 应用/Agent 方向、20–99 人小公司、只认技术负责人直招）。

要填的只有两个 Key：

| 配置 | 去哪拿 | 不填会怎样 |
| --- | --- | --- |
| 模型 API Key | DeepSeek 开放平台 | 只跑规则分，不生成招呼语，结论封顶到「待定」 |
| 检索 API Key | Tavily 或 Serper | 没有背调，缺可核验来源，同样不给绿灯 |

Key 只存在本机浏览器里，导出数据时会自动剔除。

**「简历事实库」这一栏是整个东西的地基。** 模型只能引用这里的条目当作「我会什么」的证据，
事实库里没有的技术和数字，它一律当你不具备，招呼语里也不许出现。默认内容已经按仓库根目录的
《求职事实核验表》清过一遍——没跑过的指标（QPS、召回率、自动解决率、工单条数）一条都没往里放。
别为了让招呼语好看往里加，面试官会当场问。

## 用

打开任意一个 BOSS 岗位详情页，右上角自动出现侧边栏：

- **绿灯 建议投** — 分数够、背调没矛盾、至少有一条你能点开核对的来源
- **黄灯 待定** — 分数中等，或者证据不足，或者有中风险矛盾，值得你自己看一眼
- **红灯 别投** — 硬筛没过、分数太低，或者发现高风险矛盾

绿灯和黄灯都会附一条招呼语，**文本框可以直接改**，改完再用。底下三个按钮：

| 按钮 | 干什么 |
| --- | --- |
| 复制 | 只复制到剪贴板，不碰页面 |
| 填入输入框 | 打开聊天窗并填入，**不点发送** |
| 填入并发送 | 填入后点发送（`只填不发` 开着时等同于上一个） |

红灯不生成招呼语——不打算投的岗位没必要花那次模型调用。

## 关于发送

配置页「发送」一节决定**谁按发送键**。招呼语无论如何都会生成。

- `只填不发`（默认开）：填进输入框就停手
- `绿灯岗位自动发送`（默认关）：打开后绿灯岗位不用你点。**平台对自动化投递是限制账号处理的，这个开关的后果你自己承担。**
- `黄灯岗位也自动发`（默认关）：不建议，黄灯本来就是「没把握」的意思

不管哪个模式，每次动手前都要过同一道闸（`src/domain/send-guard.js`），任何一条不满足就不发：

1. 这个岗位有没有打过招呼（去重，防重复打招呼）
2. 今天发够了没（默认上限 30）
3. **发送这一刻重新读页面**，公司名和职位名要和评估时的快照对得上——页面翻走了就停
4. 招呼语过不过校验
5. 在不在设定的发送时段内（默认 9–22 点）

注意「填入输入框」也要过这道闸。因为在 BOSS 上填招呼语得先点开聊天窗，
而点开聊天窗本身在平台口径里就已经算打过招呼了。

**发完结果不明就是不明。** 点了发送但没看到输入框被清空，会记成「待核实」并在 popup 上标出来，
**绝不重试**——重试是重复打招呼的头号来源。

页面出现验证码，立刻停手，并且把刚才记的账撤回去，这个岗位下次还能正常处理。

## 第一次用先做这件事

BOSS 的页面 class 名会改，改了抽取就会塌。

**打开第一个岗位页，先点「选择器自检」。** 它会列出每个字段是用哪层策略拿到的，
包括发送相关的那几个（沟通按钮、聊天输入框、发送按钮）：

```
jobTitle: css:.job-banner .name h1  ← AI应用开发工程师
companyName: meta                    ← 深圳某某智能科技
salaryText: text-pattern             ← 10-15K·13薪
[发送]chatInput: MISS
```

- `css:...` 走的选择器，正常
- `text-pattern` / `meta` 走的兜底，能用但不精确
- 红色 `MISS` 没拿到

抽取字段的选择器在 `src/content/boss-adapter.js` 顶部的 `SELECTORS`，
发送相关的在 `src/content/sender.js` 顶部的 `SEL`，各是一张表。

**建议先在「只填不发」模式下跑 20 个岗位**，确认结论和招呼语都对，再考虑要不要开自动发送。

## 花多少钱

一个岗位最多 3 次模型调用（匹配 + 背调归纳 + 招呼语）和 3 次检索。

- 硬筛没过的岗位**一次调用都不花**
- 红灯岗位不生成招呼语，省一次
- 同一岗位 7 天内翻回去看走缓存，不重复计费
- 配置页有每日调用上限，默认 60 次；到顶了自动降级成纯规则分

## 防幻觉

**背调**这一层挡了三道：提示词只喂检索到的片段、每条结论必须挂 URL + 原文摘录、
校验层把不在检索结果里的 URL 全部丢掉。没有来源的结论会被自动改写成「信息不足」。
反过来也防：没来源撑着的「高风险」指控降级为中风险，免得一次幻觉把好岗位毙掉。

**招呼语**这一层挡四类（`src/domain/greeting.js`）：

| 挡什么 | 例子 | 为什么 |
| --- | --- | --- |
| 编数字 | 「准确率提升 35%」「处理 160 条工单」 | 事实库里一个指标都没有，冒出来的必然是编的 |
| 编经历 | 提到事实库里不存在的项目 | 面试当场就穿帮 |
| 说空话 | 「贵司前景广阔」「深受启发」 | 发了等于没发 |
| 模板残留 | `【公司名】`、`XX科技` | 群发实锤 |

校验不过就不给招呼语，侧边栏显示「这条得你自己写」，而不是把一条含幻觉的话摆在那等你顺手发出去。

## 开发

```bash
node --test 'tests/*.test.js'
```

零运行时依赖，零构建步骤，改完代码在 `edge://extensions` 点一下刷新即可。

96 个测试覆盖：薪资/经验/学历解析、硬筛规则、打分权重、决策合并与降级、
模型输出校验与 URL 白名单、招呼语四类幻觉拦截、发送闸门的每一条规则。

还有一组结构性测试（`tests/no-send-guard.test.js`）盯着这几件事：

- **只有 `src/content/sender.js` 能操作页面**，别的 content script 里出现 `.click()` 就报错。
  想审风险的时候只需要读这一个文件。
- `sender.js` 自己不做准入判断，也不重试
- `main.js` 里过闸一定发生在碰页面之前
- 自动发送三个开关的默认值必须是关的
- 后台不许有 `chrome.alarms`，不存在「你不看着的时候它自己动」

页面 DOM 抽取只测了文本兜底那一层——CSS 选择器只能对着真站点验，这就是自检按钮存在的原因。

## 没做什么

设计文档第 5 阶段（会话解析、自动跟进、低风险自动回复）没做。
那需要持续读取聊天页面，权限和风险都上一个台阶，而且收益远不如把招呼语写好。

最后一句：**这个工具的作用是让你少投垃圾岗位，不是让你多投。**
每天有效投递数和有效回复数才是指标，工具本身不产出 offer。
