# 面试讲解与 Demo

## 3 分钟讲解稿

这是一个跨境售后客服 Agent 的面试级 MVP，定位是“AI 辅助客服”，不是自动退款机器人。前端是原生 JavaScript，后端用 FastAPI，数据落 PostgreSQL。项目默认使用本地确定性草稿生成器，所以没有 API Key 也能稳定演示；可选 DeepSeek 失败时会安全回退。

我先解决了多租户和权限的底线。所有业务表都有 `tenant_id`，所有查询都从当前 JWT 用户租户开始。角色只有客服和管理员：客服可以录入买家消息、查看订单上下文、采纳低风险草稿；管理员才可以审批高风险单。

一次买家消息会经过脱敏、语言和意图识别、风险判断、模拟订单物流查询、知识库检索、草稿生成和二次风险检查。邮件和电话在入库前就替换掉，日志也不记录正文。检索结果最多三条，并随草稿返回引用；没有命中时系统只会请人工确认或补充信息。

最核心的是风险路由。退款、赔付、结算、支付、改地址任意命中都创建人工审核单，草稿被阻塞，客服接口也无法绕过。管理员审核通过或驳回都会记录理由、操作人、时间和审计日志，但 V1 不接任何平台，所以不会发送消息、退款或改地址。这样我能把 AI 的价值放在理解和草稿上，把有资金或地址后果的动作留给人。

## 低风险物流 Demo

1. 用 `agent / demo1234` 登录，打开 Buyer-A（演示）。
2. 输入：`Where is order #CB-20512?`
3. 展示系统识别到物流诉求、查询的演示订单和物流轨迹、知识库引用与低风险草稿。
4. 点击“采纳为待发送记录”，展示状态变为 `accepted`。强调这不是外发，V1 没有消息平台 API。

## 高风险退款审核 Demo

1. 仍使用客服账号输入：`I want a refund for order #CB-20512`。
2. 展示草稿“已转人工”、高风险标记和自动创建的退款审核单。
3. 在客服账号的审核视图说明没有审批按钮；尝试直接调用审批 API 会收到 403。
4. 换 `admin / demo1234` 登录，填写理由，选择通过或驳回。
5. 展示审核人、时间、理由和最终状态；再次强调没有发生真实退款。

## 10 个技术追问

1. **为什么不直接让模型退款？** 风险规则先于模型，五类敏感请求都建人工审核单；管理员审批也不连接资金 API。
2. **如何隔离不同店铺？** 每张业务表带 `tenant_id`，router 查询以当前用户租户作为条件，跨租户返回 404。
3. **PII 如何处理？** `redaction.py` 在入库和模型调用前替换邮箱、电话；审计 metadata 有字段白名单。
4. **没有知识库命中怎么办？** 确定性生成器输出“请人工确认/补充信息”，不复述不存在的政策。
5. **DeepSeek 宕机怎么办？** `httpx.AsyncClient` 有连接和总超时；任何异常只记录错误类别并回退本地草稿。
6. **如何防模型工具越权？** V1 不开放 function calling；适配器层仍有固定工具名和 Pydantic 参数白名单，非法工具参数被拒绝。
7. **为什么还要二次风险检查？** 即使原消息低风险，模型草稿可能包含承诺性话术；发现后丢弃模型结果，换成受控的人工转交草稿。
8. **为什么 token 不放 localStorage？** Demo 同源前端仅在模块内存保存，刷新即失效，降低长期 XSS 窃取面；生产还应结合 HttpOnly Cookie/CSRF 策略评审。
9. **为什么不用向量库和 LangGraph？** 语料很小、流程固定，关键词引用和普通服务函数可解释、易跑、易测；复杂基础设施不解决 V1 问题。
10. **如何保证审计不丢？** 草稿状态、审核单和 audit log 在同一数据库事务提交；审批理由只记录长度到审计 metadata，原理由保存在审核单。
