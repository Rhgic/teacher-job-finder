# Agent 执行轨迹设计

## 目标

在客服草稿下提供默认折叠的“Agent 执行轨迹”，让面试演示能直观看到一次消息如何经过识别、工具查询、知识库检索和草稿生成。

## 方案

消息创建接口在现有响应中新增 `agent_trace`。该字段由后端管道在本次请求内结构化生成，不写入数据库，不替代现有审计日志。

每个轨迹步骤只包含：

- `stage`：`language_intent`、`risk_check`、`order_query`、`logistics_query`、`knowledge_search`、`draft_generation`、`human_review`；
- `status`：`completed`、`hit`、`miss`、`skipped`、`blocked`；
- `summary`：面向演示的固定摘要；
- `meta`：仅允许语言、意图、风险级别、知识命中数和生成器类型。

响应继续保留已有 `run_id`，用于将 UI 演示与结构化日志关联。

## 安全边界

- `agent_trace` 绝不包含买家原文、订单号、订单金额、工具参数、知识库正文、Prompt、Token、密钥或异常堆栈。
- 订单和物流工具只显示“命中 / 未命中 / 跳过”，不回显实际查询参数。
- 高风险请求以 `human_review` 的 `blocked` 步骤结束，并明确系统未执行退款、外部消息或平台写操作。
- 轨迹仅随本次接口响应返回；V1 不提供历史轨迹查询或数据库持久化。

## 前端

- 草稿下新增 `<details>` 折叠区，标题为“Agent 执行轨迹（演示）”，默认收起。
- 按后端返回顺序渲染时间线；不同状态用现有低风险/高风险色标识。
- 默认草稿详情页（历史草稿）不伪造轨迹；只显示本次新消息的真实 `agent_trace`。

## 验收

- 低风险物流场景返回完整轨迹，包含订单查询、物流查询、知识库命中和草稿生成。
- 高风险退款场景返回转人工的 `blocked` 步骤，且仍无外部操作。
- API 测试断言敏感数据不会出现在任一步的 `summary` 或 `meta`。
- 前端对新消息展示折叠轨迹；历史草稿不显示虚构轨迹。
- `pytest -q`、`ruff check app tests` 通过。
