# 店铺连接页设计

## 目标

将管理员侧的“接入中心”改造成更直观的“店铺连接”入口。用户能一眼看到 Shopify、Amazon、TikTok Shop 三类海外店铺，并能为指定平台创建现有的接入草稿或查看接入要求。

## 边界

- 继续使用已有的 `integration_configs` API 和 `draft` 状态；不改数据库、后端或 API。
- 不发起 OAuth、外部 HTTP 请求、订单同步或 webhook。
- 不收集、显示、持久化 API Key、Token、Secret。
- 页面必须显式写明“未连接（演示）”和“不会连接真实店铺”。

## 页面结构

1. 导航 tab 由“接入中心”改为“店铺连接”，仅管理员可见。
2. 页面标题为“连接海外店铺（演示）”，顶部保留真实接入未开放的边界提示。
3. 在现有表单之前新增三张平台卡：Shopify、Amazon、TikTok Shop。
   - 每张卡固定展示“未连接（演示）”。
   - 展示当前 V1 仅规划的能力：订单读取、物流查询、消息处理。
   - “创建接入草稿”会选中对应平台、滚动并聚焦到现有手动配置表单。
   - “查看接入要求”会选中对应平台、加载并聚焦到现有引导配置清单。
4. 现有“手动配置”改名为“创建接入草稿”；现有“引导配置”和“接入草稿”列表保留。

## 交互与安全

- 卡片按钮只操作现有前端选择框和现有 API；不模拟 OAuth 成功或 `connected` 状态。
- `agent` 不显示 tab 和页面入口；后端已有 403 继续作为权限边界。
- 所有平台名和能力文案来自前端固定展示文本；不伪造店铺名称、订单数或同步进度。
- 现有 `escapeHtml` 继续用于渲染后端草稿数据。

## 验收

- 管理员可见“店铺连接”tab、三张平台卡和现有草稿列表。
- 每个平台的两个按钮分别正确预选表单平台或引导清单平台。
- 创建和删除草稿仍走现有 API。
- 页面中无凭证输入框、无“已连接”或“同步中”状态。
- `pytest -q`、`ruff check app tests` 通过；浏览器验证管理员可完成上述交互，客服无入口。
